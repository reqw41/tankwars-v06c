# Tank Wars 2.5 — поле: небо, рельеф, танки, осыпание, падение

Источник: исполнение оригинала в `scripts/t03/gamerun.py` (вся игра в unicorn) + асм. Адреса — Ghidra (`re/bomb25_flat.exe`).
Модели: `scripts/ref/terrain.py`, `tanks.py`, `crumble.py`, ГСЧ `tprandom.py`. Тесты: `tests/test_terrain.py`,
`test_tanks.py`, `test_crumble.py` (сравнение с оригиналом побайтно по всему экрану 320×200).

## 0. Экран и цвета (режим 13h, 320×200)

| цвет | что | откуда |
|---|---|---|
| 0 | чёрный фон вне рамки | фон |
| 2 | земля | рельеф |
| 13 | рамка поля | `2b39:0386` |
| 20..29 | танк игрока i = 19+i | `1062:03d2` |
| 30..49 | небо (Background = 6, полосы по 8 строк) | фон |
| 130..130+R | огонь взрыва (палитра анимируется) | `318e` |

Игровое поле — вьюпорт **(11,31)–(309,189)**; рамка — контуры (8,28)–(312,192) и (10,30)–(310,190) цветом 13.
Без отражающих стен (DS:8200 = 0) добавляется линия земли y=189, x=11..309 (`2b39:0386`).
**Небо (Background 6):** строка y=31..189 закрашена цветом `30 + (y−30) div 8`. Буфер фона (DS:E0B0, 64000 байт)
= экран до рельефа (небо + рамка); им «стирают» всё (танки, воронки, осыпание). Другие варианты Background — не разобраны.

Использование буфера фона и списков: процедуры `1062:027e/046a`, `1691:0592/09cb` берут из far-указателя
**только сегмент**, смещение берётся из VRAM-смещения (`[bx]`). Если бы указатель был не на границе параграфа,
фон читался бы со сдвигом — в оригинале GetMem выравнивает, в порте просто держать буфер с нулевым смещением.

## 1. Генератор случайных чисел (TP6, `1c5b:1639`)

```
seed = seed * 0x08088405 + 1  (mod 2^32)      RandSeed = DS:3774
Random(n) = (seed >> 16) MOD n                 (1c5b:15ea — остаток DIV, не старшее слово произведения)
Random    = seed / 2^32                        (1c5b:1600 — без потерь в Real48)
```
Randomize берёт время DOS (INT 21h AH=2Ch). Совместимость раундов по сиду требует именно этой формулы.

## 2. Рельеф (`2eef:0a4f..0dbc`)

Состояние: x = DS:3EB2, h = DS:3EAA (высота над y=190), наклон s ∈ [−4..4], направление d = ±1.

```
d = 1 - 2*Random(2);  m = 60 - 7*(players-2);  h = Random(150);  s = 0;  x = 11
while x < 310:
    if x < m+11 or x > 309-m:  column(x, h); x += 1; continue          # ровные края под крайние танки
    |s|=0: col(x,h); x++; col(x,h); x++; col(x,h)
    |s|=1: col(x,h); x++; col(x,h); x++; h±=1; col(x,h)
    |s|=2: col(x,h); x++; h±=1; col(x,h); x++; h±=1; col(x,h)
    |s|=3: col(x,h); x++; h±=1; col(x,h); h±=1
    |s|=4: col(x,h); h±=1; h±=1                                        # h± : +1 если s>0, иначе −1
    if Random < 0.2:  s += d                                            # Real48 0.20000000000004547
    if Random < 0.1 or |s| > 4:  d = -d                                 # Real48 0.10000000000002274
    s = clamp(s, -4, 4)
    if h <= 20: d = 1;   if h >= 140: d = -1;   if h <= 3: s = 1;   if h >= 155: s = -1
    x += 1
column(x,h): вертикаль цветом 2 от y=190-h до y=189 включительно (1691:08ef / Graph Line)
```
Рельеф — функция высоты по столбцам (без нависаний) **только в момент генерации**; воронки и осыпание дальше
работают с пикселями (нависания возникают после взрыва и устраняются осыпанием).
Доказательство: 12 сидов × 2..6 игроков, маска цвета 2 по всему экрану совпадает (SHA1).

## 3. Расстановка и посадка танков (`2eef:0dbc..10c6`)

```
x1 = Random(28) + 16;  xN = 305 - Random(28);  q = (xN - x1) div (N-1)  (IDIV, к нулю);  xi = (i-1)*q + x1
angle = 75 для игроков 1 и N, иначе 90;  power = 200;  facing = -1 у N, иначе +1;  men = 100;  alive = 1;  y = 32
падение: если ни под одним из 9 пикселей (x-4..x+4, y+1) нет опоры {2,13}:
    повторять: стереть танк из фона; y += 1; нарисовать танк; до тех пор, пока опора есть под ВСЕМИ девятью
    затем танк со стволом (1062:059f) и рамка заново (2b39:0386)
иначе танк не рисуется (будет нарисован позже)
```
Асимметрия «начать — ни одного, закончить — все девять» означает, что на склоне танк «проседает» и оставляет
в склоне выемку (стирание из фона). Начальное здоровье **100** (поле +0x14).

**Спрайт танка** (`1062:03d2`, 33 пикселя, относительно (x,y)): строка 0: −4..+4; −1: −4,−3,−2,0,+2,+3,+4;
−2 и −3: −3..+3; −4: −1..+1. Стирание `046a` — те же пиксели из фона.
**Ствол** (`1062:059f`): линия `1691:08ef` (x,y)–(x+dx·facing, y−dy), dx = Trunc(Cos(DegToRad(a))·8),
dy = Trunc(Sin(…)·8) — **таблица в `scripts/ref/data/barrel.json`** снята исполнением RTL: TP6 даёт Cos(0)=0.99999999999454,
поэтому при 0° ствол длиной 7, при 90° — (0,7).
**Яркость танка** (`1062:07a9`) — не VRAM, а палитра: компонента = (63·men/100) div делитель игрока (+0x4D/+0x4F/+0x51);
men < 0 → чёрный.
**Линия `1691:08ef`** — Брезенхем без отсечения, концы включительно (порт побитно: `tanks.line`).
Доказательство: 6 сидов, 2..8 игроков, оба режима стен — весь экран побайтно, поля игроков.

## 4. Осыпание (`2b39:03da` → `1062:027e`)

Вызывается в ходе после выстрела, если Crumble% (DS:3EE6) > 0: рамка, затем `if Random*100 <= Crumble%` (100.0 = Real48 `87 00 00 00 00 48`).
```
«можно падать» под пикселем: цвет 0 или 30..99 (небо).  Блокируют: 1..29 (земля, рамка, танки) и ≥100.
фаза 1: для смещения bx = 0xEEC0 (191*320) вниз до 1:
          если V[bx]=2 и V[bx+320] можно: V[bx]=фон[bx]; V[bx+320]=2; список += bx+320
фаза 2: повторять, пока что-то сдвинулось: для каждого элемента e≠0 списка по порядку:
          если V[e+320] можно: V[e]=фон[e]; V[e+320]=2; e += 320   иначе e = 0
```
Список — 9999 слов (DS:823A); переполнение в оригинале не проверяется. Фаза 2 не проверяет, что V[e] ещё земля.
Падает **земля любой «высоты» до упора** — дно экрана не преграда (рамка 13 и линия земли y=189 держат).
Доказательство: 8 событий (Crumble 100/50/10, до 934 пикселей), побайтно.

## 5. Падение танков (`2b39:0020`, если Tanks Fall DS:8866 ≠ 0)

```
рамка;  для каждого игрока:
  падает = alive  и  ни под x-3..x+3 нет опоры  и  НЕ (опора под x-4 и под x+4)      (опора = {2,13})
  если не падает: перерисовать танк со стволом (059f), дальше
  стереть ствол (1691:09cb — та же линия, пиксели из фона)
  повторять:
      нарисовать танк в (x,y); y += 1
      если опора под x+4: x -= 1;  если опора под x-4: x += 1        (сползание)
      стоит = опора под всеми x-4..x+4
      если Inertia Dampener (+0x49, LongInt) > 0: dampener -= 1  иначе men -= Random(3)+1
      Delay(DS:3EE0); стереть танк в старой позиции из фона
  пока не стоит;  танк со стволом
```
Урон 1..3 за каждый пиксель падения; мёртвые (men<0, но alive=1) тоже падают — смерть обрабатывается позже.
Доказательство: 16 событий (сползание до 21 px, падение до 95 строк, Dampener 5→0), побайтно + men/dampener/RandSeed.

## 6. Для порта на Вектор-06Ц

- **Представление поля.** Оригинал хранит всё в пикселях VRAM и проверяет цвета. На Векторе (4 плоскости)
  практично держать отдельную битовую карту «земля» 300×160 (6 КБ) + рисовать её в 1–2 плоскости; небо — в другие
  плоскости, тогда «стереть из фона» = очистить бит земли/спрайта. Опора {2,13} = бит земли ∨ рамка.
- **Стоимость.** Рельеф — 300 столбцов. Танк — 33 пикселя. Осыпание: фаза 1 — проход по всему полю
  (~48 000 пикселей поля), фаза 2 — до ~100 проходов по списку до ~1000 элементов (по эталонам). На 8080 фазу 1 лучше
  делать по столбцам битовой карты (байт = 8 вертикальных пикселей) — то же поведение при обходе снизу вверх.
- **Масштаб 320→256.** Все константы поля (11..309, 31..189, 28-пиксельные зоны x танков, 305) — в пикселях оригинала;
  при уменьшении поля их надо пересчитать, точная совместимость с оригиналом по сидам при этом теряется.
