# V3. Стенд порта: сборка программы для Вектора-06Ц, запуск без окна, сравнение с эталоном

Прочитай `docs/CONTRACTS.md`, `docs/spec/v06c.md`, `docs/spec/v06c-math.md`, `web/README.md`.
Посмотри, как это уже сделано в соседнем проекте: `~/projects/cat-v06c/tools/lockstep/` (запуск эмулятора
vector06js под node, снимки экрана по тактам, сравнение с оракулом), `~/projects/cat-v06c/tools/bin/sjasmplus`
(ассемблер, режим i8080), `~/projects/cat-v06c/tools/check_i8080.py` (проверка, что в коде только команды 8080),
`~/projects/vector06js` (эмулятор). Оттуда можно брать приёмы и копировать свои вспомогательные скрипты, но те
проекты не менять.

## Зачем
Игра для Вектора будет писаться на ассемблере 8080 по эталону `web/tankwars.js` (профиль `PROFILE_V06C`).
Каждую подпрограмму надо будет сверять с эталоном: одни и те же входы — тот же экран и те же числа. Этой задачей
делается стенд, которым это проверяется, и на нём — три первые подпрограммы как доказательство, что стенд работает.
Саму игру в этой задаче писать не надо.

## Что сделать
1. **Сборка.** `v06c/build.sh` собирает `v06c/build/tw.rom` из `v06c/src/*.asm` ассемблером sjasmplus в режиме
   i8080 (скопируй бинарник в `tools/bin/` этого проекта или вызывай по пути — запиши в README, какая версия).
   Проверка, что в образе только команды 8080 (без Z80), — часть сборки. Образ грузится с адреса 0100h.
   Экран — три плоскости A000h–FFFFh (24 КБ), программа и данные — ниже A000h. Палитра программируется парами
   одинаковых цветов, чтобы плоскость 8000h–9FFFh на картинку не влияла (см. `docs/spec/v06c.md`).
2. **Запуск без окна.** `v06c/tools/run.mjs` (node): загружает образ в эмулятор vector06js, исполняет до метки
   останова или заданное число тактов, выгружает память 0000h–FFFFh и регистры в файл. Никаких окон, клавиш и
   кликов на хосте.
3. **Экран Вектора → экран эталона.** `v06c/tools/screen.mjs`: из дампа памяти трёх плоскостей получает массив
   256×256 индексов цвета 0..7 в том же виде, в каком его держит эталон (`v[y*256 + x]`). Опиши в README, как
   точка (x, y) ложится в память (адрес байта, номер бита, плоскости) — это потом пойдёт в задачу на порт.
4. **Тестовый режим образа.** Способ вызвать одну подпрограмму с заданными входами и остановиться: например,
   блок параметров по фиксированному адресу, который пишет стенд перед запуском, и метка останова после вызова.
   Способ выбери сам, опиши в README.
5. **Три подпрограммы на 8080** — те, с которых порт всё равно начнётся:
   - `Random(n)`: генератор Turbo Pascal, `seed = seed·08088405h + 1` (32 бита), результат — старшие 16 бит mod n
     (в эталоне `TPRandom.word`);
   - точка: поставить и прочитать цвет точки (x, y) в трёх плоскостях;
   - линия: в точности алгоритм `line()` из `web/tankwars.js` (он перенесён из оригинала, в нём своё правило
     обхода — не заменять на «обычный Брезенхем»).
6. **Сравнение с эталоном.** `v06c/test/run.mjs`: для каждого случая считает ожидаемое в эталоне JS
   (`setProfile(PROFILE_V06C)`), запускает образ с теми же входами, сравнивает. Случаи:
   - Random: 10 начальных значений × 1000 вызовов с разными n — последовательность и итоговый seed;
   - точка: 500 случайных точек разных цветов — весь экран;
   - линия: 300 случайных отрезков внутри поля, включая вертикальные, горизонтальные, длиной 1 и идущие справа
     налево и снизу вверх, — весь экран.
   При расхождении печатается первый случай с входами и первые отличающиеся точки.
7. **Замер.** Для каждой подпрограммы — число тактов процессора (берётся из эмулятора, не оценивается): Random,
   точка, линия длиной 10 и 200 точек. И размер кода каждой в байтах из листинга.

  в отчёт в раздел «Нужно от архитектора».

- Не писать ничего из игры сверх трёх подпрограмм.
- Не делать `git stash`, `checkout`, `reset`. `re/NOTES.md` не трогать — в нём чужая незакоммиченная правка.
  Временное — в `work/V3/`, не в /tmp.

2. `node v06c/test/run.mjs` — все случаи трёх подпрограмм совпали с эталоном; код выхода 0. Если испортить одну
   подпрограмму (я проверю, поменяв одну команду в линии), сравнение падает и показывает, где.
3. Таблица тактов и байт напечатана скриптом и совпадает с отчётом.
4. `node web/test/run_fixtures.mjs` — 910/910 и `node web/test/v06c_selfplay.mjs` — совпадает с хешами: то есть
   эталон не тронут.
5. Коммиты с префиксом `V3:`, только файлы из `v06c/`, `tools/bin/` и свой отчёт. Если упёрся больше чем на
   30 минут — запиши в «Блокеры» и иди дальше.
