# V2. Арифметика 8080 для эталона Вектора: фиксированная точка вместо Real48

Прочитай `docs/CONTRACTS.md`, `docs/spec/v06c.md`, `web/README.md`, затем сам код: `web/tankwars.js` (профили
`PROFILE_DOS` и `PROFILE_V06C`, функция `q()` и все её вызовы) и тесты в `web/test/`.

## Зачем
Эталон игры для Вектора-06Ц (`PROFILE_V06C`) пока считает как оригинал: вещественные числа Turbo Pascal (Real48,
в коде — `q(x)`), `Math.sqrt`, `Math.atan`, `Math.sin/cos`, сравнения `rng.real() < 0.2`. Процессор 8080 так считать не
будет. Нужно, чтобы профиль Вектора считал **только целыми числами заданной разрядности** — так, чтобы каждую операцию
можно было один в один повторить на ассемблере 8080. После этой задачи эталон Вектора станет окончательным: порт
должен будет совпасть с ним по хешам.

## Что сделать
1. Модуль `web/fixmath.js` — целочисленная арифметика, только операции, доступные 8080 подпрограммами:
   сложение, вычитание, сдвиги, умножение 16×16→32, деление 32/16, таблицы. Никаких `Math.*` с дробным результатом,
   никаких делений с плавающей точкой. Для каждой функции в комментарии: формат входа и выхода (сколько бит целой и
   дробной части, знак), диапазон, правило округления.
   Нужны как минимум: умножение и деление в фиксированной точке, синус и косинус по таблице (углы целые, 0..90°,
   остальное симметрией), целый квадратный корень, арктангенс в градусах (таблица или поиск по таблице тангенсов),
   сравнение случайного числа с порогом без вещественных (`Random < p` → сравнение старших 16 бит RandSeed с
   константой).
2. Флаг профиля `fixed: true` в `PROFILE_V06C`. Все места, где профиль Вектора сейчас считает в вещественных,
   получают целочисленную ветку. Список мест (проверь по коду, он может быть неполным):
   полёт снаряда и наведение (`flightDraw`), лазер, урон взрыва по расстоянию (`explode`), обломки гибели (варианты
   0 и 2), рельеф (пороги 0.2 и 0.1), ветер, выбор стен, шанс осыпания, потеря здоровья при выстреле, Explosive Dirt,
   искры гибели, планировщики ИИ (Lobber — отношение мощности к промаху; Windless Wit — решение параболы, гипотенуза,
   арктангенс; Rifleman и Twanger — шаг по лучу, арктангенс, тангенс), `chooseCode`.
   Формат координат и скоростей выбери сам и обоснуй: учти, что снаряд может улететь до y = −5000, скорость до 20
   точек за шаг, шаг делится на 10 подшагов, ускорение ветра бывает очень малым (ветер 1 → 0.00002 за подшаг).
3. **Профиль DOS не трогать по поведению.** Он сверен с настоящей игрой; ветки `fixed` включаются только флагом.
   Генератор случайных чисел `TPRandom` (32-битный LCG) оставить как есть: `Random(n)` на 8080 выполним.
4. Защита от случайного возврата к вещественным: в режиме `fixed` функция `q()` и обёртки над `Math.sqrt/atan/sin/cos`
   должны бросать исключение. В отладочном режиме проверять, что каждое значение укладывается в заявленную разрядность
   (переполнение — исключение, а не тихая ошибка).
5. Переснять золотые хеши: `node web/test/v06c_selfplay.mjs --update` — только когда всё остальное готово.

## Чего не делать
- Не менять правила игры, геометрию и цвета профиля Вектора, не трогать `web/index.html` (кроме случая, когда без
  этого страница перестаёт работать — тогда минимально и с записью в отчёте).
- Не «подгонять» ИИ: планировщики должны считать то же самое, только целыми.
- Не коммитить ничего из `work/`. Не делать `git stash`, `checkout`, `reset`. `re/NOTES.md` не трогать — в нём чужая
  незакоммиченная правка. На время задачи `web/tankwars.js` и `web/fixmath.js` — твои файлы, архитектор их не правит.

## Выходные файлы
- `web/fixmath.js`, правки `web/tankwars.js`.
- `web/test/fixmath_test.mjs` — проверка каждой функции `fixmath` против точного значения на полном диапазоне входов
  (или на плотной сетке): наибольшая ошибка печатается и сравнивается с заявленной.
- `web/test/v06c_compare.mjs` — сравнение целочисленного профиля с вещественным (тот же профиль с `fixed: false`):
  не меньше 2000 выстрелов со случайными углом, мощностью, ветром и рельефом — отклонение точки падения (среднее,
  95-й процентиль, наибольшее, в точках); 200 раундов компьютеров в каждом режиме — средняя длина раунда и доля
  попаданий по типам ИИ. Числа печатает скрипт, в отчёт они переносятся из его вывода.
- `docs/spec/v06c-math.md` — форматы чисел, таблицы (размер в байтах), каждая функция с правилом округления, оценка
  стоимости на 8080 (примерно тактов и байт кода) для умножения, деления, корня, арктангенса, шага полёта.
- `tests/fixtures/v06c/golden.json` — переснятые хеши.
- `docs/tasks/V2-report.md` — «Доказано» и «Гипотезы» раздельно, вывод всех проверок, список мест, где поведение
  изменилось сильнее ожидаемого.
