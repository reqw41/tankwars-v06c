# V3. Приёмка архитектором (03.10)

Принято с одной правкой архитектора. Гейт воспроизведён: сборка с чистого состояния, «только 8080» — 0 команд Z80;
`node v06c/test/run.mjs` — Random 10×1000, 500 точек, 300 отрезков совпали с эталоном; при порче одной команды в
линии сравнение падает и показывает точку; эталон не тронут (910/910, хеши Вектора совпадают).

## Исправлено архитектором
**Экран был перевёрнут по вертикали.** Адрес точки считался как `плоскость + (x/8)·256 + y`. У Вектора развёртка идёт
от младшего байта FFh (верхняя строка) к 00h — `vector06js/src/tv.js`: `fb_row = ScrollStart()`, затем `fb_row -= 1`.
Сравнение этого не ловило: `screen.mjs` разбирал память той же формулой, и ошибки взаимно гасились. Отчёт честно
держал ориентацию в гипотезах. Исправлено в `v06c/src/pixel.asm` (`cpl` перед записью младшего байта),
`v06c/tools/screen.mjs`, `v06c/README.md`: младший байт адреса = 255 − y.
Проверено чтением кода эмулятора; кадром с экрана эмулятора или на железе — нет.

## Замечания к порту
1. **Скорость.** Замеры из эмулятора: точка 427 тактов процессора (556 с растяжкой шины Вектора), линия — около 820
   тактов на точку, потому что зовёт общую точку с пересчётом адреса. Random — 16104 такта (около 6,5 мс при 3 МГц
   с растяжкой). Для ядра порта нужны быстрые варианты: шаг по адресу и маске вместо пересчёта, отдельная
   горизонтальная и вертикальная линия, заливка байтами. Иначе взрыв радиусом 60 (тысячи точек) будет идти секунды.
2. Считать время надо по `vcycles` (с растяжкой шины), а не по `cpu_cycles`: реальный Вектор медленнее на ~25–30 %.
3. `v06c/build/` не в `.gitignore` — добавлено.
