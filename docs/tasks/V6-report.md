## Почему цели не взяты

- **Точка 252>250.** Путь (40,50,3): x&7=0, цвет 3; `ADD HL,DE` на шаг плоскости. Не хватило 2 vcycles растяжки шины (~2 cpu). Таблица масок на этом x медленнее сдвига.
- **Кольцо 928>150/т.** 24-бит в памяти и пересчёт адреса на каждую из 4 точек. Шаг маски по квадрантам не успели довести; арифметика шага всё ещё дороже записи.
- **Танк 16236>6000, крестик 2480>1200.** Нет общего `putpixel`, прямая запись цветов 0/3/4, но адрес+маска на каждую из 33/5 точек (~490 vcycles/т. танка). Соседний шаг по SPRITE не сделан.
- **Рамка 179012>150000.** Горизонтали байтами, вертикали `DEC L`; не хватило ~16% (разворот вертикали на 2 точки почти не сдвинул).
- **Ядро 7905>5000.** UI 1643, линия 857, кольцо 930, FONT 512, осыпание 385; имена так и с выравниванием 15. Общий itoa уже был в UI; сжатие имён/дублей экранов не довели — размер вырос из-за разворотов знака и осыпания.

## Гипотезы

1. Кольцо ≤150/т. потребует четырёх курсоров (маска+HL) без 24-битных `call` в цикле.
2. Танк ≤6000 — обход SPRITE шагом маски по смежным dx,dy, без повторного `x>>3`.
3. Точка 250 — один `JP` меньше на пути цвета 3 или запись двух байт сразу, если растяжка `ADD HL,DE` меньше двух пар `LD A,H/ADD`.
