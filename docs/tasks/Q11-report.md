## Корень расхождения (ui.asm менять нельзя)

`draw_shop` расширяет корзину со знаком 16-битного числа, а эталон `TW.drawShop`
(`web/tankwars.js:1710`) трактует её беззнаково:

- MONEY: `v06c/src/ui.asm:886-894` — `p32 = {ui_cart, ui_cart+1}` и далее
  `rla` / `sbc a,a` / `ld (p32+2),a` / `ld (p32+3),a`, т.е. p32 = **знаковое** расширение
  ui_cart, затем `call ui_sub32` → рисуется `money − s16(cart)`.
- CART: `v06c/src/ui.asm:901-909` — то же знаковое расширение в `n32` → рисуется `s16(cart)`.

Для cart = 50000 = 0xC350: s16 = −15536, и 8080 печатает `MONEY  18535 ... CART -15536`
(проверено decoding'ом знаков шрифтом на реальном экране — ровно эти строки),
а эталон печатает `MONEY -47001 ... CART  50000`.

## Почему show_shop не может это обойти

Единственный канал в `draw_shop` — слово `ui_cart` (2 байта; `draw_shop` читает только
`ui_cart`, `ui_cart+1`). Поле CART на экране обязано быть `itoa(signext(ui_cart))`
= эталонное `padL(cart,6)`, то есть нужно знаковое 16-битное значение, равное cart = 50000 —
такого нет ни для каких из 8 случаев (cart ∈ {40000 … 65000} > 32767). Значит, ни при какой
подготовке ячеек из `show_shop` экран не совпадёт с эталоном. Это подтверждает и свип:
при cart ≤ 32767 (142 случая) экран совпадает целиком.

## Что нужно исправить не в Q11 (для автора)

В `draw_shop` (ui.asm:890-893 и 905-908) заменить знаковое расширение корзины на нулевое
(`rla`/`sbc a,a` → `xor a` в старшие байты p32/n32), либо ограничить генерацию теста
значениями cart ≤ 32767. После этого данная `show_shop` проходит тест без изменений
(реализация в `v06c/src/shopui.asm` остаётся в рабочем дереве, незакоммиченной).
