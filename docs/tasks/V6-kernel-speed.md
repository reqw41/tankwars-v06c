# V6. Ядро графики: скорость и размер

Прочитай `docs/CONTRACTS.md`, `docs/tasks/V5-kernel.md`, `docs/tasks/V5-report.md`, `docs/tasks/V5-review.md`,
`v06c/README.md`, затем код `v06c/src/*.asm`.

## Зачем
Ядро V5 рисует правильно (все 19 групп сравнения с эталоном зелёные), но в 2–11 раз медленнее целей и в 2,4 раза
больше по размеру. Взрыв радиуса 30 занял бы 7 секунд, осыпание — 13. Нужно ускорить и сжать, **не меняя ни одной
точки на экране**: сравнения V5 остаются как есть и должны быть зелёными после каждого шага.

## Как этого добиваться (ожидаемые приёмы; можно лучше)
- **Не звать общую точку из примитивов.** Корпус танка, крестик, знак, кольцо считают адрес и маску один раз и дальше
  шагают: вправо — сдвиг маски (при переносе `inc h`), вниз — `dec l`, плоскость — `H += 20h`.
- **Знак** — заранее готовый байт на ряд: шрифт перекодировать при сборке в 8 байт-строк на знак (или 7), знакоместо
  выровнено по байту, запись — три плоскости × 8 рядов. Перекодировку делает скрипт сборки из `FONT` эталона.
- **Кольцо**: один шаг алгоритма даёт четыре точки; обрезку по полю делать сравнением координат до расчёта адреса;
  32-битную арифметику эллипса оставить только там, где она нужна (для r ≤ 61 значения помещаются в 24 бита —
  проверь и докажи расчётом, прежде чем сужать).
- **Очистка и рамка**: развернуть цикл (по 8–16 байт на проход), горизонтали писать байтами, вертикали — шагом `dec l`.
- **Осыпание**: идти по байтовым столбцам; столбец, где во всех трёх плоскостях нет «земля над пустотой», пропускать
  целиком, проверяя байты, а не точки; ограничить обход полем (x 3..252, y 27..253).
- **Размер**: общий вывод числа и строки для трёх экранов; таблицы имён без выравнивания; убрать дублирование веток.
  Отдельно измерить: стенд и диспетчер — сколько байт; ядро — сколько.
