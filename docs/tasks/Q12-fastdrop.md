# Q12. Быстрое падение танка при расстановке на ассемблере 8080 (маленькая задача)

Нужно переписать ОДИН кусок в файле `v06c/src/place.asm` — цикл падения танка `drop_lp` в подпрограмме `place_tanks`.
Больше никакие файлы менять нельзя. Результат на экране и в таблицах должен остаться ТОЧНО прежним — меняется
только скорость.

## Проверка (единственный критерий готовности)
```
sh v06c/build.sh && node v06c/test/place.mjs
```
Готово, когда вторая команда печатает строку, начинающуюся с `OK  расстановка:`. Сейчас она печатает
`FAIL скорость: ...` — экран совпадает, но худший случай идёт 37 миллионов тактов (12 секунд), а надо не больше
6 миллионов. Если после твоей правки появится `FAIL` про экран или танки — значит, результат изменился, это ошибка.
После зелёного теста запусти ещё `node v06c/test/round.mjs` и `node v06c/test/run.mjs` — оба должны закончиться `OK ...`.

## Как сейчас (медленно)
Танк ставится в точку (x, 28). Если под ним нет опоры ни в одном из девяти столбцов x−4 .. x+4, он падает по шагу:
```
повторять:
    erase_tank(x, y)            ; стереть корпус — 33 точки цветом 0
    y = y + 1
    draw_tank(x, y, цвет)       ; нарисовать корпус — 33 точки
пока не станет: во ВСЕХ девяти столбцах dx = −4..4 есть опора sup(x + dx, y)
```
`sup(x, y)` (подпрограмма `pt_supx`) смотрит цвет точки (x, y + 1) — строкой НИЖЕ танка; опора — цвет 1 или 2.
Корпус занимает строки y−4 .. y, поэтому стирание и рисование корпуса НЕ меняют точки, которые проверяет `sup`.
Значит, конечную высоту можно найти без рисования.

## Как надо (быстро)
```
1. y_конец: начиная с y = 29, увеличивать y на 1, пока не станет «во всех девяти столбцах sup(x + dx, y)».
   (То же условие и тот же порядок, что сейчас в all_lp, только без erase_tank и draw_tank. В pt_y в итоге
   должно лежать y_конец — дальше код берёт его оттуда.)
2. шагов = y_конец − 28                                   ; не меньше 1
3. если шагов == 1:
       erase_tank(x, 28)                                  ; как раньше: один раз стереть корпус в начальной точке
   иначе — стереть след танка девятью вертикальными отрезками цвета 0:
       для dx = −4 .. 4:   отрезок в столбце x + dx от строки верх(dx) до строки y_конец − 1 включительно,
       где верх(dx) = 24 для dx = −1, 0, 1;   25 для dx = −3, −2, 2, 3;   27 для dx = −4, 4
4. draw_tank(x, y_конец, цвет)                            ; D = x, E = y, A = номер игрока + 3 — как сейчас
5. дальше без изменений: ствол (draw_tank_barrel), рамка (draw_frame), запись в таблицы.
```
Почему след — отрезки: корпус в столбце dx занимает строки от y + (верх(dx) − 28) до y; за два и больше шагов
падения эти строки сливаются в сплошной отрезок от верх(dx) до y_конец − 1. При одном шаге — нет (в столбцах
dx = ±1 у корпуса есть дырка), поэтому один шаг стирается по-старому, через erase_tank.

## Вертикальный отрезок
Готовая подпрограмма `line` (`v06c/src/line.asm`): вход — слова `ln_x1`, `ln_y1`, `ln_x2`, `ln_y2` и байт `ln_c` (цвет).
Для вертикального отрезка: `ln_x1 = ln_x2 = x + dx` (старший байт слова 0), `ln_y1 = верх(dx)`, `ln_y2 = y_конец − 1`,
`ln_c = 0`, затем `call line`. `line` портит все регистры — счётчик dx держи в ячейке памяти (`pt_dx` уже есть).
Записать слово в ячейку: `ld l, a` / `ld h, 0` / `ld (ln_x1), hl`.

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Новые метки и ячейки начинай с `pt_`; ячейки данных — рядом с остальными `pt_*` в конце файла.
