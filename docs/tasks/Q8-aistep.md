`round_winner`. Больше никакие файлы менять нельзя.

## Данные
Игрок на месте i (1..n) — запись `players + (i − 1)·PL_SIZE`; `n_players` — число игроков. Поля (`v06c/src/player.inc`):
- текущее состояние: `PL_ANGLE` (байт 0..90), `PL_FACING` (байт: 1 или 0xFF = −1), `PL_POWER` (слово), `PL_MEN` (слово со
  знаком), `PL_ALIVE` (байт), `PL_WEAPON` (байт), `PL_AMMO + 2·w` (слово со знаком — запас оружия w; запас оружия 5 —
  «энергия»);
- план компьютера: `PL_AI_PLAN` (байт «план готов»), `PL_AI_POWER` (слово СО ЗНАКОМ), `PL_AI_ANGLE` (байт),
  `PL_AI_FACING` (байт 1 или 0xFF), `PL_AI_WEAPON` (байт), `PL_AI_N` (байт — счётчик истории).

## choose_code (A = место) → A = код
```
1. пока запас[план.оружие] < 1:                         ; запас — слово со знаком
       план.оружие = план.оружие − 1;  если стало меньше 0:  план.оружие = 12
2. если 10·men < план.мощность:  план.мощность = 10·men   ; сравнение СО ЗНАКОМ; 10·men может быть <= 0
3. если план.оружие == 5 и запас[5] < план.мощность:  план.мощность = запас[5]
4. если план.мощность < 0:  план.мощность = 0
5. код = 5
   t = 0, если facing == 1;  t = −1, если facing == −1
   если angle < план.угол:   код = 1 − t              ; то есть 1 при facing = 1 и 2 при facing = −1
   если angle > план.угол:   код = t + 2              ; то есть 2 при facing = 1 и 1 при facing = −1
   если power > план.мощность:  код = 3
   если power < план.мощность:  код = 4
   если facing != план.направление:  код = 6
   если weapon != план.оружие:  код = 8
   (каждая следующая проверка перебивает предыдущую — порядок важен)
6. если код == 3 и power − план.мощность > 99:  power = power − 90
   если код == 3 и power − план.мощность > 9:   power = power − 9       ; проверяется уже с новым power
   если код == 4 и план.мощность − power > 99:  power = power + 90
   если код == 4 и план.мощность − power > 9:   power = power + 9       ; проверяется уже с новым power
7. если код == 5:  PL_AI_PLAN = 0
8. вернуть код в A; изменённые power, план.оружие, план.мощность записать в запись
```
`PL_POWER` — число 0..1000. Сравнения мощностей — со знаком (16 бит).

## turn_begin (A = место)
`PL_AI_N = PL_AI_N + 1` (байт).

## next_alive (A = cur, от 0 до n) → A
```
повторять:
    cur = cur + 1;  если cur > n:  cur = 1
пока игрок на месте cur не жив (PL_ALIVE == 0)
вернуть cur
```
Гарантируется, что хотя бы один игрок жив.

## round_winner → CF, A
```
посчитать живых игроков (PL_ALIVE != 0)
если живых больше одного:  CF = 0
если живой ровно один:     CF = 1, A = его место
если живых нет:            CF = 1, A = 0
```

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Все свои значения храни в ячейках памяти (`db`/`dw`), имена своих меток и ячеек начинай с `ai_`. Ячейки данных
размещай ПОСЛЕ метки `aistep_end`. Образцы стиля — `v06c/src/action.asm`, `v06c/src/shop.asm`.
Подсказка для сравнения слов со знаком: есть готовая подпрограмма `fl_scmp` (flight.asm): вход HL и DE,
выход A = 0 (равны), 1 (HL > DE), 0xFF (HL < DE); портит B.

Метки `choose_code`, `turn_begin`, `next_alive`, `round_winner`, `aistep_end` должны остаться с этими именами.
