## Доделать

   на раунд (и, если есть, меняет его между ходами). Для каждого режима None/Norm/High/Gale снять по ≥ 1000
   значений (разные RandSeed) и дать min/max/гистограмму. Модель генерации — в `scripts/ref/wind.py`, тест
   совпадения последовательностей с оригиналом при одном и том же RandSeed (`tests/test_wind.py`).
   Сценарии ветра в `test_ballistics` дополнить значениями из реального диапазона Gale, включая крайние.
2. **Условие конца полёта, спека, строка 75:** «`power < 1000−2*men` … → done=1» выглядит как неверно названная
   переменная или ветка конкретного оружия. Разобрать, что на самом деле сравнивается (адрес, тип), и переписать
   пункт. Если это ветка «Ball o Dirt», так и указать.
3. **Fixed-point под 8080.** «18/25 точек падения совпало» — мало информации для решения. Нужно:
   - для каждого из 25 сценариев: максимальное отклонение траектории в пикселях и смещение точки падения
     (dx, dy) для вариантов **16.16**, **8.8 скорость + 16.8 позиция** и **24.8 позиция + 8.16 скорость**
     (или другой обоснованный вариант 24-битной арифметики);
   - объяснить источник расхождений (накопление при `vy += 0.01`? константа 1/5000 не представима?);
   - рекомендация: какой формат брать для 8080, с таблицей «ошибка / стоимость операций на шаг»;
   - оценка числа шагов: в трассах до 1619 записанных позиций. Сколько подшагов в секунду должна тянуть
     8080 на 3 МГц, чтобы полёт шёл не медленнее оригинала с Cycle Delay по умолчанию (задержку взять из кода).
   Результат — раздел 9 спеки и `work`-независимый скрипт `scripts/ref/fp_compare.py`, вывод которого
   цитируется в отчёте.
4. Обозначение угла: метка `a180_p200` на деле — угол 0 с facing=−1. Переименовать или добавить настоящий
   крайний случай, а в спеке явно описать систему «угол 0..90 + направление».
