# Q11. Экран магазина по записям игроков на ассемблере 8080 (маленькая задача)

Нужно написать ОДНУ подпрограмму `show_shop` в файле `v06c/src/shopui.asm`. Больше никакие файлы менять нельзя.

## Проверка (единственный критерий готовности)
```
sh v06c/build.sh && node v06c/test/shopui.mjs
```
Готово, когда вторая команда печатает строку, начинающуюся с `OK  экран магазина по записям:`. Пока печатает
`FAIL ...` — не готово: в сообщении написаны входы и первые точки экрана, которые не совпали. После зелёного теста
запусти ещё `node v06c/test/hud.mjs`, `node v06c/test/shop.mjs`, `node v06c/test/run.mjs` — все должны закончиться `OK ...`.

## Что это
Экран магазина рисует готовая подпрограмма `draw_shop` (`v06c/src/ui.asm`, прочитай её заголовок и метку `do_shop` в
`v06c/src/tw.asm` — там видно, какие ячейки она ждёт). Она читает игрока в «упакованном» виде (80 байт) и меню по
4 байта на позицию. Твоя задача — переходник, как в Q9 (`v06c/src/hud.asm`, прочитай: там `show_panel` делает то же
самое для панели): из записи игрока и списков магазина собрать то, что ждёт `draw_shop`, и вызвать её.

## Вход show_shop
- A = место игрока 1..n;
- `su_sel` (байт) — выбранная строка (0xFF — ничего не выбрано);
- `sh_count` (байт) — число позиций меню (0..22);
- `sh_cat[i]`, `sh_num[i]`, `sh_qty[i]` — байтовые массивы по 22 элемента (`v06c/src/shop.asm`): категория, номер и
  количество покупок позиции i;
- `sh_cart` — корзина, 4 байта; `draw_shop` берёт только младшие 2 байта.

## Что сделать (по шагам)
```
1. упаковать игрока на месте A в блок 80 байт — готовой подпрограммой hd_pack1 из hud.asm:
       hd_place = A;  hd_blk = 0;  call hd_pack1        ; блок окажется в hd_pack
2. собрать меню в su_menu: для i = 0 .. sh_count − 1 четыре байта:
       su_menu[4·i + 0] = sh_cat[i]
       su_menu[4·i + 1] = sh_num[i]
       su_menu[4·i + 2] = sh_qty[i]        ; количество — слово: младший байт
       su_menu[4·i + 3] = 0                ; старший байт
3. заполнить ячейки draw_shop:
       ui_cart   = младшие 2 байта sh_cart (слово)
       ui_sel    = su_sel
       ui_nmenu  = sh_count
       ui_menu   = адрес su_menu (слово)
       ui_p      = адрес hd_pack (слово)
4. call draw_shop;  ret
```
Если `sh_count` = 0, шаг 2 пропустить (цикл не должен выполниться ни разу).

## Если не сходится
Сначала проверь свои шаги: правильные ли адреса, не портит ли `hd_pack1` твои регистры (она портит все — счётчики
держи в ячейках). Если уверен, что расхождение внутри `draw_shop` (файл ui.asm менять нельзя) — запиши в файл
`docs/tasks/Q11-report.md` входы из сообщения FAIL и что именно рисуется не так, и остановись.

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Свои метки и ячейки начинай с `su_`; ячейки данных размещай ПОСЛЕ метки `shopui_end` (там уже есть `su_sel` и `su_menu`).
