# Q5. Перерисовка танков, осыпание и падение после выстрела на ассемблере 8080 (маленькая задача)

Нужно написать ОДНУ подпрограмму `after_shot` в файле `v06c/src/after.asm` (сейчас там заглушка `after_shot: ret`).
Подпрограмму `rnd_le_pct` в том же файле НЕ менять — она готова. Больше никакие файлы менять нельзя.

## Проверка (единственный критерий готовности)
```
sh v06c/build.sh && node v06c/test/after.mjs
```
Готово, когда вторая команда печатает строку, начинающуюся с `OK  после выстрела:`. Пока печатает `FAIL ...` — не
готово: в сообщении написано, что не совпало (поле записи игрока, RandSeed или первая точка экрана). После зелёного
теста запусти ещё `node v06c/test/round.mjs`, `node v06c/test/explode.mjs`, `node v06c/test/run.mjs` — все должны
закончиться `OK ...`.

Это перенос начала функции `afterShot` и функций `crumbleGate`, `tanksFall` из `web/tankwars.js` (прочитай их, а также
`drawTankBarrel`, `drawTank`, `eraseTank`, `sup`).

## Данные
- `n_players` (байт), `players` — записи игроков по `PL_SIZE` байт, игрок на месте i (1..n) — запись номер i − 1.
  Поля (`v06c/src/player.inc`): `PL_X`, `PL_Y`, `PL_ANGLE`, `PL_FACING` — байты; `PL_MEN` — слово со знаком;
  `PL_ALIVE` — байт; `PL_DAMP` — 4 байта (демпфер, неотрицательное число).
- `as_crumble` — процент осыпания, `as_fall` — 0/1, `as_rebound` — 0/1.
- Экран 256×256: цвет 0 фон, 1 земля, 2 рамка, 4..7 танки игроков 1..4.

## Алгоритм (порядок менять нельзя)
```
1. для каждого игрока i = 1..n:  нарисовать танк со стволом (draw_tank_barrel; он сам ничего не рисует, если игрок мёртв)
2. если as_crumble > 0:
       draw_frame с A = as_rebound
       rnd_le_pct с A = as_crumble;  если CF = 1:  call crumble
3. если as_fall != 0:
       draw_frame с A = as_rebound
       для каждого игрока i = 1..n по порядку:
           falling = (PL_ALIVE != 0)
           если хотя бы для одного dx из −3..3 выполняется sup(x + dx, y):  falling = 0
           если sup(x − 4, y) и sup(x + 4, y):  falling = 0
           если falling == 0:
               нарисовать танк со стволом (draw_tank_barrel)        ; у мёртвого ничего не нарисуется
               перейти к следующему игроку
           стереть ствол: линия цвета 0 от (x, y) до конца ствола    ; см. «Как стереть ствол» ниже
           повторять:
               ox = x;  oy = y
               нарисовать корпус в (ox, oy) цветом i + 3             ; draw_tank
               y = y + 1
               если sup(x + 4, y):  x = x − 1
               если sup(x − 4, y):  x = x + 1                        ; x здесь уже может быть изменён строкой выше
               landed = «для всех dx из −4..4 выполняется sup(x + dx, y)»
               если PL_DAMP > 0:  PL_DAMP = PL_DAMP − 1
               иначе:  PL_MEN = PL_MEN − (Random(3) + 1)             ; Random берётся ТОЛЬКО в этой ветке
               стереть корпус в (ox, oy)                             ; erase_tank
           пока landed ложно
           записать новые x, y в PL_X, PL_Y
           нарисовать танк со стволом (draw_tank_barrel)

sup(x, y):  цвет точки (x, y + 1) равен 1 (земля) или 2 (рамка)
```
Обрати внимание: новые x и y надо держать в записи игрока (или записать перед `draw_tank_barrel`), а
`draw_tank_barrel` читает координаты из ячеек `tb_x`, `tb_y`, а не из записи.

## Готовые подпрограммы (их не менять, только вызывать)
Все портят регистры AF, BC, DE, HL — свои счётчики, указатели и координаты храни в ячейках памяти (`db`/`dw`).
- `draw_tank_barrel` (barrel.asm): вход в ячейках `tb_x`, `tb_y` (байты), `tb_idx` (байт, место игрока 1..4),
  `tb_angle` (СЛОВО), `tb_facing` (байт 1 или 0xFF), `tb_alive` (байт; если 0 — ничего не рисует).
- Как стереть ствол: заполнить те же ячейки `tb_*`, затем `call tb_ends` (он записывает концы ствола в ячейки линии),
  затем `xor a` / `ld (ln_c), a` / `call line`.
- `draw_tank` (sprite.asm): вход D = x, E = y, A = цвет. `erase_tank`: вход D = x, E = y.
- `getpixel` (pixel.asm): вход D = x, E = y; выход A = цвет.
- `draw_frame` (frame.asm): вход A = 0 или 1.
- `crumble` (crumble.asm): без входа — осыпание земли на экране.
- `rnd_le_pct` (в этом же файле): вход A = процент; выход CF = 1 — «осыпать».
- `random` (random.asm): вход DE = n, выход HL = Random(n).

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Имена своих меток начинай с `af_`. Образцы стиля — `v06c/src/place.asm`, `v06c/src/round.asm`.

Метки `after_shot`, `after_end`, `rnd_le_pct`, `as_crumble`, `as_fall`, `as_rebound`, `as_pct` должны остаться.
Метка `after_end` должна стоять сразу после конца твоего кода (перед ячейками данных).
