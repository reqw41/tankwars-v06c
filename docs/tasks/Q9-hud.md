# Q9. Панель хода и экран результатов по записям игроков на ассемблере 8080 (маленькая задача)

Нужно написать ДВЕ подпрограммы в файле `v06c/src/hud.asm`: `show_panel` и `show_results`.
Больше никакие файлы менять нельзя.

## Проверка (единственный критерий готовности)
```
sh v06c/build.sh && node v06c/test/hud.mjs
```
Готово, когда вторая команда печатает строку, начинающуюся с `OK  панель и результаты`. Пока печатает `FAIL ...` — не
готово: в сообщении написаны первые несовпавшие точки экрана. После зелёного теста запусти ещё
`node v06c/test/aistep.mjs`, `node v06c/test/action.mjs`, `node v06c/test/run.mjs` — все должны закончиться `OK ...`.

## Суть
Подпрограммы рисования уже есть в `v06c/src/ui.asm`: `draw_panel` и `draw_results`. Они рисуют правильно, но читают
игрока не из записи `players`, а из «упакованного» блока в 80 байт. Нужен переходник: собрать из записи игрока
упакованный блок и вызвать готовую подпрограмму. Саму отрисовку писать НЕ надо.

## Запись игрока (откуда брать) — `v06c/src/player.inc`
Игрок на месте i (1..n) — запись `players + (i − 1)·PL_SIZE`. Нужные поля: `PL_NAME` (до 13 знаков и байт 0),
`PL_FACING` (байт), `PL_ANGLE` (байт), `PL_POWER` (слово), `PL_MEN` (слово), `PL_WEAPON` (байт), `PL_GUIDED` (байт),
`PL_HERB`, `PL_VICK`, `PL_WINS` (слова), `PL_SCORE`, `PL_SPENT` (по 4 байта), `PL_SHIELD`, `PL_DAMP` (по 4 байта),
`PL_AMMO` (18 слов).

## Упакованный блок, 80 байт (куда класть)
| смещение | размер | что |
|---|---|---|
| 0 | 16 | имя, заканчивается байтом 0 (скопировать 14 байт из `PL_NAME`, остальное — нули) |
| 16 | 1 | место игрока (1..4) |
| 17 | 1 | направление (как `PL_FACING`) |
| 18 | 2 | угол (слово: младший байт — `PL_ANGLE`, старший — 0) |
| 20 | 2 | мощность |
| 22 | 2 | здоровье (`PL_MEN`) |
| 24 | 1 | оружие |
| 25 | 1 | наведение (`PL_GUIDED`) |
| 26 | 2 | `PL_HERB` |
| 28 | 2 | `PL_VICK` |
| 30 | 2 | победы (`PL_WINS`) |
| 32 | 4 | очки (`PL_SCORE`) |
| 36 | 4 | потрачено (`PL_SPENT`) |
| 40 | 2 | щит — младшие 2 байта `PL_SHIELD` |
| 42 | 2 | демпфер — младшие 2 байта `PL_DAMP` |
| 44 | 36 | 18 слов запаса (`PL_AMMO`) |
Место для блоков уже есть: `hd_pack` (4 блока по 80 байт).

## show_panel (A = место игрока)
```
упаковать запись этого игрока в hd_pack (первый блок)
ui_wind = rs_wind                 ; слово (rs_wind — в round.asm)
ui_p = адрес hd_pack              ; слово
call draw_panel
```

## show_results (hd_round, hd_rounds — уже заполнены вызывающим)
```
упаковать записи всех игроков 1..n_players в hd_pack подряд (блок i − 1 — по адресу hd_pack + (i − 1)·80)
ui_round = hd_round;  ui_rounds = hd_rounds;  ui_n = n_players       ; байты
ui_ps = адрес hd_pack                                                ; слово
call draw_results
```

Как эти ячейки заполняет стенд, видно в `v06c/src/tw.asm` в метках `do_panel` и `do_results` — посмотри.
`draw_panel` и `draw_results` портят все регистры.

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Свои значения храни в ячейках памяти (`db`/`dw`), имена своих меток и ячеек начинай с `hd_`, ячейки размещай после
метки `hud_end`. Копировать кусок памяти удобно готовой `fx_copy` (fx.asm): HL = куда, DE = откуда, B = сколько байт
(после неё HL и DE стоят сразу за скопированным).

Метки `show_panel`, `show_results`, `hud_end`, `hd_round`, `hd_rounds`, `hd_pack` должны остаться с этими именами.
