# T03 — отчёт: рельеф, взрывы, осыпание, падение танков

Выполнено архитектором (по просьбе пользователя) вместо исполнителя; черновик исполнителя
`work/T03/crumble-tanks-fall.md` использован как отправная точка, всё в нём перепроверено исполнением.

## Главное изменение метода: вся игра в unicorn
`scripts/t03/gamerun.py` запускает BOMB.EXE 2.5 с entry, как DOS: PSP, куча TP, файлы из `orig/` (BOMB.CFG, BOMB*.RAW,
bomb.ovr), INT 21h/10h/16h/1Ah/33h, порты VGA (DAC, 3DA), тик BIOS (калибровка Crt Delay), оверлеи в верхней памяти
(стабы INT 3Fh → JMP FAR). Заставка → меню → экран игроков (ИИ задаются клавишами) → раунд, кадры в PNG.
Эталоны сняты не «вызовом процедуры с выдуманным состоянием», а в настоящей игре; на входах подменялись только
параметры (оружие, звук, Crumble%, щиты, цвет попадания), дальше работает оригинал.

Уроки стенда (для следующих задач):
- `emu_start(until=…)` в unicorn ненадёжен для уже транслированного кода — останов сделан хуком (`Game.run`).
- Хук-событие на адресе срабатывает повторно при продолжении с того же адреса — нужен «пропуск первого».
- Во время хода игра читает клавиатуру своим INT 9 через таблицу DS:3B90 (по скан-коду), не через INT 16h.
  Поэтому эталоны снимаются с игроками-компьютерами (`computer_keys()`).

## Доказано
- ГСЧ TP6: `Random(n) = (seed>>16) mod n`, `Random = seed/2^32` — 175 сравнений с RTL (`test_tprandom_matches_rtl`).
- Рельеф `2eef:0a4f..0dbc`: целочисленный, s∈[−4..4], вероятности — Real48 0.2/0.1; спека `docs/spec/terrain.md` §2.
- Небо (Background 6) = полосы `30+(y−30) div 8`; буфер фона = экран до рельефа (проверено: 0 различий).
- Расстановка/посадка танков, спрайт 33 px, ствол — таблица из RTL (`Cos(0)` даёт ствол длиной 7), рамка
  перерисовывается после каждого севшего танка.
- Обычный взрыв `318e:00e0`: R = 10/15/30/60/2; огонь и воронка — кольца средней точки вокруг (cx±1, cx); урон
  `1.5R / R / 0.7R`, щит (+0x45) поглощает первым, очки стрелку 10×перелив; ГСЧ только на звук.
- Осыпание `1062:027e` и вход `2b39:03da`; падение `2b39:0020` с Inertia Dampener (+0x49), уроном Random(3)+1 за пиксель,
  перерисовкой всех живых танков.
- **Circle/EMULATE:** в настоящей игре (настоящий InitGraph) Circle рисует: во взрыве CRI `Circle(288,65,7)` → 40 px,
  размах ровно 2r (`tests/fixtures/t03/circle_real.json`). Тест T01b с хуком стенда этого не доказывает (другая копия
  драйвера, без InitGraph).

## Гипотезы / не проверено
- Расстояние Hypot считается в модели в double, а не в Real48: на 28 эталонах расхождений нет, но на точных границах
  порогов (d = 1.5R, R, 0.7R; Trunc(1.8R−d) у целого) возможны различия. При порте на fixed-point это всё равно
  перерешается.
- Другие варианты Background (DS:8860) не разобраны — только 6 (по умолчанию в BOMB.CFG 2.5).
- Переполнение списка осыпания (>9999 пикселей в фазе 1) не моделируется (в оригинале портит память).
- «Explotions Kill» (DS:8203) в разобранных сегментах (318e, 2583, 2b39, 1062) не встречается — где используется, неизвестно.

## Поправки к прошлым задачам
- **T01b:** `1827:1028` = **GetViewSettings** (используется `1691:0006`, пишет вьюпорт в DS:E3AC). Тест эллипса
  в `test_graph.py` рисуется хуком стенда — для доказательства отрисовки есть `test_circle_real.py`.
- **T02:** в начале раунда здоровье танков = **100**, а не 5–10 (сценарии T02 использовали men=5/10). Значит, порог
  «пролёта сквозь землю» `1000−2·men` в реальной игре = 800 при полном здоровье, а формула «max power = 100×men»
  из спеки T02 требует перепроверки (при men=100 давала бы 10000). `2583:140f`, названный в T02 TW_ExplosionDispatch, —
  это ход Laser (оружие 5, множество `2583:2511`), а не диспетчер взрывов.
