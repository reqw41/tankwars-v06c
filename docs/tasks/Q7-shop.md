# Q7. Магазин компьютерного игрока на ассемблере 8080 (маленькая задача)

Нужно написать ОДНУ подпрограмму `ai_shop` в файле `v06c/src/shop.asm` (сейчас там заглушка `ai_shop: ret`).
Таблицы цен и пачек в том же файле НЕ менять. Больше никакие файлы менять нельзя.

## Проверка (единственный критерий готовности)
```
sh v06c/build.sh && node v06c/test/shop.mjs
```
Готово, когда вторая команда печатает строку, начинающуюся с `OK  магазин ИИ:`. Пока печатает `FAIL ...` — не готово:
в сообщении написаны номер случая, стратегия и какие поля записи не совпали. После зелёного теста запусти ещё
`node v06c/test/match.mjs`, `node v06c/test/action.mjs`, `node v06c/test/run.mjs` — все должны закончиться `OK ...`.

Это перенос функций `aiShop`, `shopMenu`, `aiChoice`, `shopCommit`, `shopAdd`, `shopHave` из `web/tankwars.js`
(прочитай их все).

## Данные
Вход: A = место игрока 1..n. Его запись — `players + (A − 1)·PL_SIZE`. Поля (`v06c/src/player.inc`):
- `PL_SCORE`, `PL_SPENT` — 4 байта со знаком. Деньги = score − spent (32 бита).
- `PL_STRAT` — байт, стратегия 0..4.
- `PL_AMMO + 2·w` — запас оружия w (слово со знаком), w = 0..17.
- `PL_HERB`, `PL_VICK` — слова (категория 1: номер 0 — Herb, 1 — Vick).
- `PL_SHIELD`, `PL_DAMP` — по 4 байта (категория 2: номер 0 — щит, 1 — демпфер).
Таблицы в shop.asm: `sh_wprice`, `sh_wpack` (оружие, по слову на w), `sh_gprice`, `sh_gpack` (категория 1),
`sh_dprice`, `sh_dpack` (категория 2).

## Алгоритм
```
money = score − spent
если money < 3000 или стратегия == 0:  выйти, ничего не меняя

; 1. меню — список позиций (категория, номер), не больше 22 штук
для w от 0 до 17:   если пачка[w] != 0 и (запас[w] > 0 или цена[w] <= money):   добавить (0, w)
для i от 0 до 1:    если (есть наведение i > 0) или (цена_g[i] <= money):        добавить (1, i)
для i от 0 до 1:    если (есть защита i > 0) или (цена_d[i] <= money):           добавить (2, i)
у каждой позиции счётчик qty = 0;   cart = 0   (cart — 32 бита)

; 2. покупки: не больше 10000 повторов
повторять:
    left = money − cart                                   ; 32 бита со знаком
    sel = «нет»
    стратегия 1:
        для позиций c от ПОСЛЕДНЕЙ к первой:
            если категория == 0 и номер w от 1 до 4 и (запас[w] + пачка[w]·qty[c] < 20) и цена[w] <= left:   sel = c
    стратегия 2 (hi = 4) или 3 (hi = 5):
        для позиций c от ПЕРВОЙ к последней:
            если категория == 0 и номер w от 1 до hi и цена[w] <= left:   sel = c
        затем: если запас[1] + 100·qty[0] < 20:   sel = 0            ; позиция 0 — первая в меню
    стратегия 4:
        для позиций c от ПОСЛЕДНЕЙ к первой:
            если категория == 2 и цена_d[номер] <= left:   sel = c
        затем: если запас[1] + 100·qty[0] < 20:   sel = 0
    если sel == «нет»:  закончить покупки
    price = цена позиции sel
    если qty[sel] < 9 и price <= left:   cart = cart + price;  qty[sel] = qty[sel] + 1
    иначе если qty[sel] >= 9:            закончить покупки
    (иначе — просто следующий повтор)

; 3. оплата
для каждой позиции c с qty[c] > 0:
    spent = spent + цена·qty[c]                            ; 32 бита
    прибавка = пачка·qty[c]
    категория 0: запас[w] = запас[w] + прибавка            ; слово
    категория 1: herb или vick += прибавка                 ; слово
    категория 2: shield или damp += прибавка               ; 4 байта
```
«sel = c» внутри цикла каждый раз перезаписывает sel: остаётся ПОСЛЕДНЯЯ подошедшая позиция по ходу обхода.
«запас[w] + пачка·qty < 20» — обычные числа со знаком, помещаются в слово.

Подсказки:
- Меню удобно держать в трёх массивах по 22 байта: категория, номер, qty — и счётчик позиций.
- Умножение на qty (0..9) — сложением в цикле.
- Сравнение «цена <= left», где left — 32 бита со знаком, а цена — слово 0..20000: если left отрицательное — ложь;
  если старшее слово left не ноль — истина; иначе сравни младшее слово left с ценой беззнаково.
- Своих подпрограмм можно писать сколько угодно, но только в этом файле.

## Правила ассемблера (важно)
Синтаксис — мнемоники Z80 в sjasmplus, но процессор 8080: разрешены только команды, которые есть у 8080.
Нельзя: `jr`, `djnz`, `ix`, `iy`, `ex af`, `exx`, `ldir`, `bit`/`set`/`res`, `sla`/`sra`/`srl`/`rl`/`rr` (кроме `rla`, `rra`,
`rlca`, `rrca`), `neg`, `sbc hl`, `adc hl`, `ld bc,(nn)`, `ld de,(nn)`, `ld (nn),bc`, `ld (nn),de`.
Нельзя писать `sub (метка)`, `cp (метка)` или `ld e,(метка)` — sjasmplus примет это за число. Значение из ячейки бери
так: `ld a,(метка)`, а слово — `ld hl,(метка)`.
Можно: `ld hl,(nn)`, `ld (nn),hl`, `ld a,(nn)`, `ld (nn),a`, `add hl,de`, `ex de,hl`, `jp`, `jp z/nz/c/nc/m/p`, `call`, `ret`,
`inc`/`dec`, `cp`, `sub`, `sbc a`, `add a`, `adc a`, `and`, `or`, `xor`, `cpl`, `push`/`pop`.
Все свои значения храни в ячейках памяти (`db`/`dw`/`ds`), имена своих меток начинай с `sh_`.
Образцы стиля — `v06c/src/action.asm`, `v06c/src/match.asm`.

Метки `ai_shop`, `shop_end`, `sh_wprice`, `sh_wpack`, `sh_gprice`, `sh_gpack`, `sh_dprice`, `sh_dpack` должны остаться.
Метка `shop_end` должна стоять сразу после конца твоего кода, перед таблицами и ячейками данных.
