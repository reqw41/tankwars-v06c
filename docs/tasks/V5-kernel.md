# V5. Ядро графики порта: быстрые примитивы трёх плоскостей, сверенные с эталоном

Прочитай `docs/CONTRACTS.md`, `v06c/README.md`, `docs/tasks/V3-report.md`, `docs/tasks/V3-review.md`,
`docs/spec/v06c.md`, `docs/spec/v06c-screen.md`. Стенд уже есть (задача V3): `sh v06c/build.sh`,
`node v06c/test/run.mjs`.

## Зачем
Подпрограммы V3 писались, чтобы проверить стенд, и они медленные: точка — 427 тактов процессора, линия — около 820
тактов на точку, потому что на каждую точку заново считает адрес и маску. Игра рисует тысячи точек на взрыв, так
она идти не сможет. Нужна библиотека примитивов, из которых потом собирается вся игра: каждый даёт **тот же экран**,
что соответствующая функция эталона `web/tankwars.js` в профиле `PROFILE_V06C`, и каждый написан на скорость.

## Что сделать
Все примитивы — в `v06c/src/`, по файлу на группу. Экран — три плоскости A000h/C000h/E000h, цвет 0..7, адрес байта
`плоскость + (x/8)·256 + (255 − y)`, бит 7 — левая точка. Точка вне 0..255 не пишется и читается как 0.

| № | примитив | функция эталона, с которой сверять |
|---|---|---|
| 1 | точка: поставить, прочитать | запись и чтение `v[y*256+x]` |
| 2 | линия | `line(v, x1, y1, x2, y2, c)` — тот же обход, не «обычный Брезенхем» |
| 3 | линия стирания | `line(..., bg)` при нулевом фоне: те же точки, цвет 0 |
| 4 | рамка поля | `drawFrame(v, rebound)` — два прямоугольника и нижняя линия земли без стен |
| 5 | корпус танка | `drawTank(v, x, y, c)` и `eraseTank` (33 точки `SPRITE`) |
| 6 | танк со стволом | `drawTankBarrel(v, t)` — таблица ствола `web/data/barrel.json` (углы 0..90), `eraseTankBarrel` |
| 7 | кольцо эллипса | `ring(v, cx, cy, r, color)` и `ringRestore` при нулевом фоне, с обрезкой по полю (`VIEWPORT`), r = 0..61 |
| 8 | мяч-крестик | `cross(v, null, x, y, 3)` и стирание `cross(v, bg, x, y)` при нулевом фоне |
| 9 | знак и строка | `drawChar`, `drawText` — шрифт `FONT` (320 байт, 64 знака) |
| 10 | панель и экраны | `drawPanel`, `drawResults`, `drawShop` — можно собрать из п. 9; состояние игроков подаётся стендом |
| 11 | очистка | весь экран; строки 0..23; замена цвета 3 на 0 по всему экрану (`replaceTmp`) |
| 12 | осыпание | `crumbleColumns(v, bg)` при нулевом фоне |
| 13 | палитра | запись 16 регистров палитры парами одинаковых цветов (см. `docs/spec/v06c.md`, «Память»); цвета танков — `tankRGB(p)` → R,G `>> 3`, B `>> 4` |

Требования к скорости — не «как получится», а цель; замер по `vcycles` эмулятора (с растяжкой шины):
- точка, поставить: не больше 250;
- линия: не больше 150 на точку для длинной (200 точек) линии; горизонтальная и вертикальная — отдельными быстрыми
  путями (горизонтальная цвета 0 или сплошная может писать байтами);
- кольцо радиуса 30: не больше 120 на точку;
- знак 8×8: не больше 1500; очистка всего экрана: не больше 350 000;
- осыпание на экране с типичным рельефом и одной воронкой радиуса 30: замерить и записать (цели нет).
Если цель не достигнута — оставь лучший вариант, запиши замер и что мешает. Не подгоняй замер.

Приёмы, которые ожидаются: шаг по адресу и маске вместо пересчёта (вправо — сдвиг маски, вниз — `dec l`, так как
строка ниже = адрес меньше на 1); таблица масок; запись сразу в три плоскости через `H += 20h`; для колец — восемь
(четыре) симметричных точки от одного шага алгоритма с обрезкой по полю.

Сравнение с эталоном — в `v06c/test/run.mjs`, по образцу V3: случайные входы с фиксированным начальным числом,
ожидаемый экран считает `web/tankwars.js`, сравнивается весь экран 256×256. На каждый примитив не меньше 200
случаев (для экранов п. 10 — не меньше 5 состояний каждого), обязательно крайние: точки и кольца у рамки и за ней,
танк у края поля, линии всех восьми направлений и длиной 1, углы ствола 0, 45, 90 в обе стороны, пустая строка и
строка в 32 знака, осыпание на пустом экране и на экране без пустот.

## Чего не делать
- Не менять `web/`, `tests/`, `scripts/`, `re/`, `docs/spec/`. Если в эталоне чего-то не хватает — запиши в отчёт
  «Нужно от архитектора».
- Не писать игровую логику (полёт, взрыв с уроном, ИИ) — только примитивы из таблицы.
- Не трогать соседние проекты. Не делать `git stash`, `checkout`, `reset`. `re/NOTES.md` не трогать.
  Временное — в `work/V5/`.
- Старые медленные подпрограммы V3 можно заменить новыми, но тесты V3 (Random, точка, линия) должны остаться зелёными.

1. `sh v06c/build.sh` с чистого состояния; «только 8080» — 0 команд Z80.
2. `node v06c/test/run.mjs` — все примитивы совпали с эталоном, код выхода 0. Порча одной команды в любом примитиве
   (проверю на двух) роняет сравнение.
3. Таблица тактов и байт печатается скриптом и совпадает с отчётом; по каждой цели скорости сказано, достигнута ли.
4. Общий размер ядра — в отчёте (ожидание: до 3,5 КБ вместе со шрифтом и таблицами; если больше — объяснить).
5. `node web/test/run_fixtures.mjs` — 910/910 и `node web/test/v06c_selfplay.mjs` — совпадает с хешами.
