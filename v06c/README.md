# Стенд порта Tank Wars на Вектор-06Ц (задача V3)

Подпрограммы на 8080 сверяются с эталоном `web/tankwars.js` (`PROFILE_V06C`): сборка образа, запуск в vector06js без окна, перевод трёх плоскостей в `v[y*256+x]`, сравнение.

Сама игра здесь не пишется — только Random, точка и линия.

## Одной командой

Из корня репозитория:

```
sh v06c/build.sh && node v06c/test/run.mjs
```

Сборка должна напечатать `check_i8080: … Z80-only 0` и `OK: v06c/build/tw.rom`. Сравнение — код выхода 0 и строки `OK  Random` / `OK  точка` / `OK  линия`, затем таблицу тактов и байт.

Ассемблер: **SjASMPlus Z80 Cross-Assembler v1.24.0**, бинарник `tools/bin/sjasmplus`, флаг `--i8080` (как в cat-v06c). Проверка «только 8080» — `v06c/tools/check_i8080.py` по листингу.

Эмулятор: `~/projects/vector06js` (или каталог в `VECTOR06JS`). Не меняется; подключается из `v06c/tools/run.mjs` через `vm`.

## Карта памяти образа

| диапазон | что |
|---|---|
| 0000h–007Fh | не в ROM; 0038h не используется (DI) |
| **0080h** | блок параметров стенда (`PARAM`) |
| 0100h…`rom_end` | код: вход, палитра, диспетчер, Random, точка, линия |
| **2000h** | список входов (`LIST`), стенд пишет перед запуском |
| **7000h** | результаты (`RESULT`) |
| стек вниз от **9F00h** | в плоскости 8000h, на картинку не влияет |
| 8000h–9FFFh | плоскость 0 (не цвет игры) |
| A000h–BFFFh | плоскость 1, бит 0 цвета 0..7 |
| C000h–DFFFh | плоскость 2, бит 1 |
| E000h–FFFFh | плоскость 3, бит 2 |

Образ грузится с **0100h**. Программа и данные тестов — ниже A000h (список 2000h, результаты 7000h).

Палитра: индекс железа `idx = (p0<<3)|(p1<<2)|(p2<<1)|p3`. Цвет игры `c = p1 + 2·p2 + 4·p3`. Слоты `i` и `i+8` получают один и тот же байт цвета, поэтому бит плоскости 8000h картинку не меняет.

## Как точка (x, y) ложится в плоскости

Координаты эталона: `x, y` в 0..255, **y=0 сверху**, индекс `v[y*256 + x]`.

- Столбец байта: `col = x >> 3` (0..31).
- Адрес в плоскости: `plane_base + col*256 + y`.
- Бит в байте: **бит 7 — левая** точка столбца, маска `80h >> (x & 7)`.
- Базы: A000h (bit0), C000h (bit1), E000h (bit2). Плоскость 8000h в цвет 0..7 не входит.

То же в `v06c/tools/screen.mjs` (`pixelLoc`, `planesToScreen`).

Вне 0..255 точка не пишется и читается как 0 (как `clip` эталона).

## Тестовый режим

Стенд перед запуском пишет:

1. **PARAM (0080h), 16 байт**
   - +0 режим: 1 Random, 2 точки, 3 линии, 4 замер одной подпрограммы
   - +1 вид замера: 1 Random, 2 точка, 3 линия
   - +2 слово: число элементов списка
   - +4 dword: `RandSeed` (little-endian), после Random записывается обратно
   - +8 слово: `n` для замера Random
   - +10..14: `x, y, x2, y2, c` для замера точки/линии
2. **LIST (2000h)**
   - Random: `count` слов `n`
   - точки: тройки `x, y, c`
   - линии: `x1, y1, x2, y2, c`
3. Образ стартует с 0100h, в конце **HLT** (метка `done`).
4. **RESULT (7000h)**: слова Random; байты `getpixel` после рисования точек.

Замер тактов: метки `bench_*_call` / `bench_*_ret` в `.sym`. Счётчик — `cpu.cpu_cycles` эмулятора (такты 8080: ADD=4, CALL=17), с первой команды тела до возврата включительно. `vcycles` (растяжки Вектора) печатаются рядом, в таблицу не входят.

CLI: `node v06c/tools/run.mjs v06c/build/tw.rom [--dump mem.bin] [--halt done]`.

## Как добавить подпрограмму и случай

1. Файл в `v06c/src/`, `include` из `tw.asm`. Только команды 8080 (`jp`/`dec`, не `jr`/`djnz`/`ix`). Метки `имя` и `имя_end` для размера.
2. Режим в диспетчере: код в PARAM+0, входы в LIST, выход в RESULT или в плоскостях.
3. В `v06c/test/run.mjs`: посчитать эталон через экспортированное из `web/tankwars.js` (`setProfile(PROFILE_V06C)`), запустить образ, сравнить. При расхождении — первый случай и первые точки.
4. Эталон не править. Если функции нет в экспорте — раздел «Нужно от архитектора» в отчёте, не патч `web/`.

Линия — копия управления `line()` из `web/tankwars.js` (своя вертикаль/горизонталь и обмен концов при cx<0), не «обычный Брезенхем».
