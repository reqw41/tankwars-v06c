# Стенд порта Tank Wars на Вектор-06Ц (V3 стенд, V5 ядро графики)

Подпрограммы на 8080 сверяются с эталоном `web/tankwars.js` (`PROFILE_V06C`): сборка образа, запуск в vector06js без окна, перевод трёх плоскостей в `v[y*256+x]`, сравнение.

Сама игра здесь не пишется. Ядро графики (V5): точка, линия, рамка, танк, кольцо, текст, панель, очистка, осыпание, палитра.

## Одной командой

Из корня репозитория:

```
sh v06c/build.sh && node v06c/test/run.mjs
```

Сборка должна напечатать `check_i8080: … Z80-only 0` и `OK: v06c/build/tw.rom`. Сравнение — код выхода 0 и строки `OK` по каждому примитиву, затем таблицу тактов и байт.

Ассемблер: **SjASMPlus Z80 Cross-Assembler v1.24.0**, бинарник `tools/bin/sjasmplus`, флаг `--i8080` (как в cat-v06c). Проверка «только 8080» — `v06c/tools/check_i8080.py` по листингу.

Эмулятор: `~/projects/vector06js` (или каталог в `VECTOR06JS`). Не меняется; подключается из `v06c/tools/run.mjs` через `vm`.

## Карта памяти образа

| диапазон | что |
|---|---|
| 0000h–007Fh | не в ROM; 0038h не используется (DI) |
| **0080h** | блок параметров стенда (`PARAM`) |
| 0100h…`rom_end` | код: вход, диспетчер, примитивы |
| **4000h** | список входов (`LIST`), стенд пишет перед запуском |
| **7000h** | результаты (`RESULT`) |
| стек вниз от **9F00h** | в плоскости 8000h, на картинку не влияет |
| 8000h–9FFFh | плоскость 0 (не цвет игры) |
| A000h–BFFFh | плоскость 1, бит 0 цвета 0..7 |
| C000h–DFFFh | плоскость 2, бит 1 |
| E000h–FFFFh | плоскость 3, бит 2 |

Образ грузится с **0100h**. Программа и данные тестов — ниже A000h. LIST на **4000h**, потому что ROM ядра ~8,5 КБ уже занимает диапазон бывшего LIST 2000h.

Палитра: индекс железа `idx = (p0<<3)|(p1<<2)|(p2<<1)|p3`. Цвет игры `c = p1 + 2·p2 + 4·p3`. Слоты `i` и `i+8` получают один и тот же байт цвета, поэтому бит плоскости 8000h картинку не меняет.

## Как точка (x, y) ложится в плоскости

Координаты эталона: `x, y` в 0..255, **y=0 сверху**, индекс `v[y*256 + x]`.

- Столбец байта: `col = x >> 3` (0..31).
- Адрес в плоскости: `plane_base + col*256 + (255 - y)`: младший байт FFh — верхняя строка экрана (развёртка Вектора идёт от FFh вниз к 00h).
- Бит в байте: **бит 7 — левая** точка столбца, маска `80h >> (x & 7)`.
- Базы: A000h (bit0), C000h (bit1), E000h (bit2). Плоскость 8000h в цвет 0..7 не входит.

То же в `v06c/tools/screen.mjs` (`pixelLoc`, `planesToScreen`).

Вне 0..255 точка не пишется и читается как 0 (как `clip` эталона).

## Тестовый режим

Стенд перед запуском пишет:

1. **PARAM (0080h), 16 байт**
   - +0 режим: 1 Random … 16 экраны (см. `MODE_*` в `tw.asm`)
   - +1 вид замера / подвид очистки / вид экрана (0 панель, 1 результаты, 2 магазин)
   - +2 слово: число элементов списка
   - +4 dword: `RandSeed` (little-endian), после Random записывается обратно
   - +8 слово: `n` для замера Random
   - +10..14: `x, y, x2, y2, c` для замера точки/линии
2. **LIST (4000h)** — входы случая: точки, отрезки, упакованные игроки (80 байт) и т.д.
3. Образ стартует с 0100h, в конце **HLT** (метка `done`).
4. **RESULT (7000h)**: слова Random; байты `getpixel`; 16 байт палитры.

Замер тактов: метки `bench_*_call` / `bench_*_ret` в `.sym`. Цель по скорости — **`vcycles`** эмулятора (растяжка шины). Рядом печатается `cpu_cycles`.

CLI: `node v06c/tools/run.mjs v06c/build/tw.rom [--dump mem.bin] [--halt done]`.

## Как добавить подпрограмму и случай

1. Файл в `v06c/src/`, `include` из `tw.asm`. Только команды 8080 (`jp`/`dec`, не `jr`/`djnz`/`ix`). Метки `имя` и `имя_end` для размера.
2. Режим в диспетчере: код в PARAM+0, входы в LIST, выход в RESULT или в плоскостях.
3. В `v06c/test/run.mjs`: посчитать эталон через экспортированное из `web/tankwars.js` (`setProfile(PROFILE_V06C)`), запустить образ, сравнить. При расхождении — первый случай и первые точки.
4. Эталон не править. Если функции нет в экспорте — раздел «Нужно от архитектора» в отчёте, не патч `web/`.

Линия — копия управления `line()` из `web/tankwars.js` (своя вертикаль/горизонталь и обмен концов при cx<0), не «обычный Брезенхем».

## Ядро графики

Экран: три плоскости A000h/C000h/E000h, цвет 0..7, адрес `плоскость + (x/8)·256 + (255 − y)`, бит 7 слева. Стенд сравнивает весь экран 256×256 с функциями эталона в `PROFILE_V06C`.

Такты и байты — из вывода `node v06c/test/run.mjs` / `display` сборки (не прикидка).

| примитив | вход | что портит | байт | такты (vcycles) |
|---|---|---|---:|---:|
| Random | `DE` = n, семя в `rand_seed` | семя; HL = результат | 294 | 19740 (n=100) |
| putpixel | `D`=x `E`=y `A`=цвет | три плоскости | 88 (put+get+addr 196) | 272 |
| линия | `ln_x1/y1/x2/y2` слова, `ln_c` | точки линии | 857 | 15460 / 200 т. (77,3 на точку) |
| рамка | `A`=rebound | рамки цветом 2; земля 1 если A=0 | 272 | 597996 |
| корпус танка | `D,E,A`; стирание цветом 0 | 33 точки SPRITE (8 бит с переносом) | 79 | 29892 |
| крестик | `D,E,A` | 5 точек CROSS | 56 | 3756 |
| кольцо | `ring_cx/cy` слова, `r`, `c` | эллипс в VIEWPORT | 912 | 223084 (r=30) |
| очистка | `fill_screen` / `clear_panel` | 3×8К или y=0..23 | 95 | 692680 (весь экран) |
| ствол | `tb_*` | корпус + линия по `barrel_tab` | 141 (+182 таблица 0..90) | вместе с танком |
| знак | `ch_col/row/ch/c` | знакоместо 8×8, фон 0 | 242 (+320 FONT) | 15276 («A») |
| осыпание | экран уже в плоскостях | столбцы, bg=0 | 154 | 39032864 (рельеф + воронка r=30) |
| replaceTmp | экран | цвет 3→0, кроме (0,0) | 35 | — |
| палитра | men и делители RGB по 4 игрокам | PPI + порт 0Ch; 16 байт в RESULT | 333 | — |
| панель / результаты / магазин | `ui_p` / `ui_ps` / меню | панель y=0..23 или весь экран; результаты ещё `draw_frame` rebound=1 | 1643 (+имена и цены) | — |

Запись игрока 80 байт в LIST: имя 16 (0-терминатор), idx, facing, angle, power, men, weapon, guided, herb, vick, wins, score (i32), spent (i32), shield, damp, ammo[18].

- Панель: ветер i16 + игрок.
- Результаты: round, rounds, n, игроки.
- Магазин: cart i16, sel (255 = −1), nmenu, затем nmenu×(cat, i, qty i16), затем игрок.
